### Phase 1 진입 Gate-Check

본 주차는 AP-Framework V0.41의 **Phase 1 (관리)** 단계에 해당하며,
실습 시작 전 Phase 0 산출물이 모두 갖춰져 있어야 합니다.

```
[ Gate-Check: Phase 0 -> Phase 1 진입 조건 ]

  필수 산출물                                        상태
  --------------------------------------------------  ----
  [ ] PRD.md 프로젝트 개요 작성 완료                    ?
  [ ] .AP-key.md 서비스 키 기입 완료                    ?
  [ ] 00.통합자료실/ 5개 폴더 구조 + 참조 자료 5건       ?
  [ ] NotebookLM 노트북 생성 + 소스 6건 이상 동기화      ?
  [ ] GitHub PAT 발급 (repo + workflow + project 권한)  ?
  [ ] .progress.md 의 Phase 0 항목 4건 = 완료           ?

  -> 6개 항목이 모두 "완료"여야 W2 실습을 시작할 수 있다.
```

수강생은 수업 시작 5분 안에 `.progress.md`의 Phase 0 섹션을 직접 확인하고,
미완료 항목이 있으면 TA에게 즉시 보고합니다.

수업 완료 후 수강생은 다음을 수행할 수 있다:

#### GitHub vs Jira 비교

| 항목 | GitHub Projects | Jira |
|------|----------------|------|
| 비용 | 무료 (Public) | 유료 ($7.75+/user) |
| 학습 곡선 | 낮음 | 높음 |
| 코드 연동 | 네이티브 | 플러그인 |
| 보고서 | 기본 수준 | 고급 대시보드 |
| 적합 대상 | 소규모/MVP | 엔터프라이즈 |

#### `.progress.md`: Document Chain의 단일 진실 공급원


## 4. 실습 가이드 -- AP-Rodi-Shop 예제

### 4.1 실습 1: GitHub 프로젝트 셋업 (40분)

**목표**: Projects 보드, Milestones, Issue 템플릿, 라벨 체계를 구축한다.
**사전 조건**: W1 과제 완료 + Phase 0 Gate-Check 통과
**사용 프롬프트**: 없음 (수동 설정)

#### Step-by-Step

**Step 1: GitHub Projects V2 보드 생성 (10분)**

> **중요**: GitHub Projects V2는 **사용자(User) 레벨**에서 생성합니다.
> 사용자 프로필 > Projects > New project -> Board 템플릿 선택 후 저장소에 Link.

1. github.com > 프로필 > "Your projects" > "New project"
2. Board 템플릿 선택, 이름: "[프로젝트명] 관리 보드"
3. 기본 칼럼 + "Review" 칼럼 추가 (To Do / In Progress / Review / Done)
4. 저장소 Link: 프로젝트 Settings > Repository 추가

**추가 뷰 + 커스텀 필드** (Roadmap 사용 시):

| 항목 | 설명 |
|------|------|
| Table 뷰 | 전체 일람 |
| Roadmap 뷰 | Gantt 형식 (Start/End Date 필드 필수) |
| Priority 필드 | P0/P1/P2 |

**Step 2: Milestones 생성 (10분)**

| Milestone | 마감일 | 설명 |
|-----------|--------|------|
| M1. 환경 구축 완료 | W1 종료일 | Phase 0 산출물 |
| M2. 관리 산출물 완료 | W2 종료일 | 착수보고서, WBS, 주간보고서 |
| M3. 기획 산출물 완료 | W3 종료일 | 기획 7건 + 중간보고서 |
| M4. 구현 완료 | W4 종료일 | 코드 + 인프라 |
| M5. 프로젝트 종료 | W5 종료일 | 검수 + 완료보고서 |

> AP-Rodi-Shop 실전 결과: 5개 Milestones, 31개 Issues, 100% 완료

**Step 3: 라벨 체계 (10분)**

| 라벨 | 색상 | 용도 |
|------|------|------|
| `priority/high` `/medium` `/low` | 빨/주/노 | 우선순위 |
| `type/document` `/code` `/infra` | 파/초/보 | 작업 종류 |
| `phase/W1` ~ `phase/W5` | 회색 | 주차 |

**Step 4: Issue 템플릿 확인 + 테스트 (10분)**

V0.41의 `.github/ISSUE_TEMPLATE/` 3종 확인:
- `task.md` -- 일반 태스크
- `feature-request.md` -- 기능 요청
- `bug-report.md` -- 버그 리포트

테스트 Issue 1건 생성 (Milestone + 라벨 + Projects 보드 자동 연결 확인).

**품질 체크포인트**:
- [ ] Projects 보드 4칼럼 구성
- [ ] Milestones 3개 이상
- [ ] 라벨 5개 이상
- [ ] 테스트 Issue가 보드에 표시

**트러블슈팅**:

| 현상 | 원인 | 해결 |
|------|------|------|
| Projects 탭 없음 | 저장소 Features 비활성 | Settings > Features > Projects on |
| Issue 보드 미표시 | V2 저장소 미연결 | 프로젝트 Settings에서 Repository 추가 |
| Roadmap 바 없음 | Date 필드 미설정 | Fields에 Start/End Date 추가 |
| PAT 권한 부족 | `project` 스코프 누락 | PAT 재발급 시 `repo, workflow, project` 체크 |

### 4.5 실습 5: n8n WF 01·02 import + Webhook 연결 (30분)

**목표**: V0.41이 제공하는 n8n 워크플로우 JSON 2건을 n8n Cloud에 import하고 가동.
**사용 워크플로우**: `n8n/01-github-issue-slack.json`, `n8n/02-weekly-summary-slack.json`

#### Step-by-Step

**Step 0: n8n Cloud 가입 + Credential 준비 (5분, W2 신규 — W1에서 이관)**

> W1에서는 n8n을 다루지 않으므로, **W2 첫 실습에서 n8n Cloud 가입을 진행**합니다.

1. **n8n Cloud 가입** (app.n8n.cloud → Sign up, Free 플랜)
2. **Slack Incoming Webhook URL 발급** (교육 채널에 강사가 사전 추가한 Webhook)
3. **GitHub PAT 확인** (W1 사전 설치 시 발급한 PAT, 권한: repo · workflow · project)
4. n8n Cloud > Settings > Credentials → **GitHub API** Credential 등록 + Test → "Connection successful"

> Slack Incoming Webhook은 Credential이 아님 — 워크플로우 내 HTTP Request 노드에 URL 직접 입력.

**Step 1: 워크플로우 JSON 확인 (5분)**

V0.41 저장소에 이미 포함된 2개의 JSON을 확인:

| 파일 | 트리거 | 동작 |
|------|--------|------|
| 01-github-issue-slack.json | GitHub Webhook (Issue opened/closed/labeled) | Slack 알림 |
| 02-weekly-summary-slack.json | Schedule (매주 금요일 17:00 KST) | 주간 요약 Slack |

**Step 2: n8n Cloud에 import (10분)**

1. n8n Cloud > Workflows > "..." > Import from File
2. `01-github-issue-slack.json` 업로드
3. **Credential ID는 비어 있음** -- 수강생이 직접 GitHub/Slack Credential 등록
   - GitHub Credential: PAT 입력
   - Slack: HTTP Request 노드에 Incoming Webhook URL 직접 입력 (Credential 아님)
4. 02 워크플로우도 동일하게 import

> **강사 노트**: Credential ID가 비어 있어 처음 열면 노드가 빨갛게 표시됨.
> 이는 정상. 각 노드를 클릭하여 Credential을 직접 연결하라고 안내.

**Step 3: GitHub Webhook 연결 (10분)**

1. 저장소 > Settings > Webhooks > Add webhook
2. Payload URL: n8n Webhook 노드의 **Production URL** (Test URL 아님)
3. Content type: application/json
4. Events: Issues 체크
5. Add webhook
6. 테스트: GitHub Issue 1건 생성 -> Slack 알림 수신 확인

**Step 4: 워크플로우 Active 전환 (5분)**

n8n Cloud에서 두 워크플로우를 모두 "Active"로 전환.

**트러블슈팅**:

| 현상 | 원인 | 해결 |
|------|------|------|
| import 실패 | JSON 손상 | Claude Code에 검증 요청 |
| Webhook 미동작 | 비활성 | "Active" 전환 |
| Slack 메시지 미수신 | Webhook URL 오류 | HTTP 노드에 URL 재입력 |
| Test URL 응답 | Production URL 미사용 | Production URL로 교체 |

| 기획자 출신 PM | 산출물 작성 경험 풍부 | "AI 초안 -> PM 검수" 비교에 초점, P-205/P-206 도전 권장 |
| 개발자 출신 PM | GitHub 익숙, 산출물 형식 미숙 | 산출물 "왜 이 형식인가" 설명, .progress.md 자동화 흥미 유도 |

### 시간 조절 가이드

| 상황 | 조치 |
|------|------|
| 과제 리뷰 + Gate-Check 초과 | Gate-Check만 5분 압축, 우수 사례 1건 |
| 실습 1 빠르게 완료 | 실습 3의 P-203에 시간 추가 |
| n8n import 실패 다수 | 강사 라이브 시연 + JSON Slack 배포 |
| 전체 빠르게 진행 | P-205 경영진 요약 실습 추가 |
| 전체 느리게 진행 | 실습 5(n8n)와 실습 6(.progress.md 갱신)를 과제로 전환 |

### 핵심 강조 포인트

1. **프롬프트 라이브러리는 검증된 자산**: P-201~P-208은 AP-Rodi-Shop 실전 검증을 거친 8개 프롬프트. "처음부터 프롬프트를 새로 짜지 않는다."
2. **Document Chaining 첫 경험**: 착수보고서 -> WBS -> Issues -> 주간보고서로 이어지는 체이닝. 각 단계의 출력이 다음의 입력.
3. **.progress.md = 단일 진실 공급원**: 산출물 생성만으로 끝나지 않음. 상태 갱신을 빠뜨리면 다음 주차 Phase Gate가 막힌다.
4. **AI 80% + PM 20%**: AI는 초안을, PM은 판단(범위/리스크/우선순위)을 한다.
5. **n8n은 "접착제"**: GitHub과 Slack을 연결하여 수동 상태 보고를 자동화.

### 주의 사항

- P-203 실행 시 `gh` CLI 필요. 미설치자 사전 안내
- PAT은 `repo + workflow + project` 3종 권한 필수
- n8n WF는 Credential ID가 비어 있음. 수강생이 직접 등록해야 함을 명확히
- Slack Incoming Webhook은 Credential 타입 아님 -- HTTP Request URL에 직접 입력
- `.progress.md` 갱신 시 다른 행 건드리지 않도록 "범위 한정" 프롬프트 사용
- P-205, P-206은 본 주차 미실습. 시간 부족 시 과제 5로 전환
