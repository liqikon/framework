### 핵심 개념 1: Document Chaining DAG (V0.41 신규)

이번 주차의 가장 큰 변화는 **체이닝을 "순차 라인"이 아니라 "DAG(방향성 비순환 그래프)"** 로 본다는 점이다. 각 산출물은 자신의 전제조건(앞 문서)이 **모두 완료된 경우에만** 생성을 시작할 수 있다. 이 의존관계는 `.progress.md`의 `Document Chain Status` 표에 명시되어 있다.

```
                     PRD.md
                       |
        +--------------+--------------+
        v                             v
   #1 착수보고서                   #3 마켓리서치 (P-301)
        |                             |
        v                             v
   #2 WBS                         #4 서비스기획서 (P-302)
                                      |
                                      v
                              #5 요구사항정의서 (P-303)
                                      |
                                      v
                              #6 기능명세서 (P-304) <-- 분기점
                                      |
        +-----------+-----------+-----+-----+
        v           v           v           v
   #7 API스펙  #8 정보구조도 #11 시스템   #15 테스트
   (P-305)    (P-306)      정의서       시나리오
                              |              |
        +--------+ +----------+              |
        |        | |                         v
        v        v v                    (Phase 4 검수)
   #9 화면설계서 (P-307)
        |
        v
   #10/#12/#13 (Group B, Phase 3)
```

**핵심 메시지**: #6 기능명세서가 끝나면 `(#7, #8, #11, #15)`가 **동시에** 실행 가능해진다. 이 4개는 서로 입력 의존성이 없으므로 P-309 한 번으로 병렬 생성할 수 있다 -- **이번 주차 실습 4의 하이라이트**.

### 핵심 개념 2: Phase 2 Gate-Check

V0.41은 Phase 단위로 진행을 통제한다. W3 진입을 위한 Phase 1 Gate, W3 종료 시점의 Phase 2 Gate를 명확히 한다.

| Phase | 산출물 | Gate 통과 조건 |
|-------|--------|----------------|
| Phase 1 (관리) | #1 착수보고서, #2 WBS | 두 산출물 모두 `.progress.md`에서 상태=완료 |
| Phase 2 (기획) | #3 ~ #9 + (선택) #11, #15 | #3 ~ #9 모두 완료, Group A 4건 중 최소 #7, #8 완료 |

**목표**: P-301로 마켓리서치를 수행하고, P-302로 서비스기획서를 체이닝 생성한다.

**사전 조건**: Phase 1 Gate 통과 (#1 착수보고서, #2 WBS 완료) + 통합자료실 존재

#### Step-by-Step

**Step 0: `.progress.md` 전제조건 확인 (2분)**

```bash
claude ".progress.md를 열어서 Phase 1 Gate (#1, #2)가 모두 완료 상태인지,
그리고 #3 마켓리서치의 전제조건(PRD.md 존재)이 만족되는지 확인해줘."
```

**Step 1: P-301 마켓리서치 생성 (18분)**

```bash
claude "P-301 실행:
PRD.md의 프로젝트 개요를 기반으로 마켓리서치를 수행해줘.

조사 항목:
1. 타겟 시장 규모와 성장률 (글로벌 + 국내)
2. 주요 경쟁 서비스 분석 (최소 5개 플랫폼 비교)
3. 기술 동향과 산업 트렌드 (3건 이상)
4. 사용자 니즈와 Pain Point

웹 검색을 활용하여 실제 데이터를 기반으로 작성하고,
리서치 자료 10건 이상을 정리해줘.
02.기획문서/마켓리서치.md에 저장하고,
완료 후 .progress.md의 #3 상태를 '완료'로, 완료일을 오늘 날짜로 갱신해줘."
```

> AP-Rodi-Shop 예시 -- 마켓리서치 핵심 발췌:
>
> **경쟁 환경 분석**:
>
> | 경쟁사 | 유형 | 수수료 | 강점 | 약점 |
> |--------|------|--------|------|------|
> | 인프런 | 국내 교육 | 30% | IT 교육 1위, 트래픽 | 높은 수수료, 전자책 미지원 |
> | Class101 | 국내 교육 | 20~30% | 브랜드 인지도 | 구독 전환, 개별 판매 축소 |
> | Udemy | 글로벌 교육 | 37~67% | 글로벌 규모 | 매우 높은 수수료, 가격 통제 어려움 |
> | Gumroad | 글로벌 DTC | 10% | 낮은 수수료 | 영어 중심, 한국 결제 불편 |
>
> **시장 기회**: 국내 온라인 교육 시장 8.3조원 + 전자책 시장 1.4조원. AI 교육 수요 전년 대비 40%+ 증가.
>
> **핵심 차별화**: 수수료 3~5% vs 기존 15~67%, 강의+전자책 번들 자유 구성, 구매자 데이터 직접 소유.
>
> 참조: `AP-Rodi-Shop/02.기획문서/마켓리서치.md` (완성본)

**Step 2: P-302 서비스기획서 생성 (15분)**

```bash
claude "P-302 실행:
마켓리서치.md를 기반으로 서비스기획서를 작성해줘.

포함 섹션:
1. Executive Summary (한 줄 요약 + 핵심 지표)
2. 서비스 배경 및 시장 기회 (마켓리서치 데이터 인용)

7. 개발 전략 (기술 스택, 마일스톤)
8. 리스크 관리
9. 성공 KPI

마켓리서치의 데이터를 근거로 인용해줘.
02.기획문서/서비스기획서.md에 저장하고,
.progress.md의 #4 상태를 '완료'로 갱신해줘."
```

| 실습 4(P-309) 병렬 실행이 막힘 | Task 도구 호출 예시를 화면 시연 후 4개 중 2개만 병렬, 나머지 2개는 순차로 우회 |
| 실습 5(화면설계서)가 어려워하는 수강생 다수 | 핵심 3개 화면만 작성, 나머지는 과제로 |
| 전체적으로 빠르게 진행 | P-308 HTML 프로토타입 진행: `claude "화면설계를 Tailwind 기반 HTML로 만들어줘"` |
| 전체적으로 느리게 진행 | 실습 6(NotebookLM 갱신)을 과제로 전환, 실습 4에 시간 집중 |

### 핵심 강조 포인트

1. **V0.41 프롬프트 라이브러리 활용**: P-301~P-309는 입력/출력/전제조건이 표준화된 재사용 자산. 매 산출물 생성마다 동일한 패턴이 반복되어야 한다.
2. **DAG 사고**: 7단계 체이닝을 단순 순차로 보지 말고, `.progress.md`의 의존관계 표를 매번 확인하라. 분기점(#6)을 만나면 즉시 병렬화.
3. **P-309의 가속 효과**: 순차 60분 → 병렬 20분. 토큰은 비슷하게 쓰되 시간을 3배 단축. 이것이 Claude Code Task 도구의 진짜 가치.
4. **`.progress.md` = 단일 진실 공급원**: 모든 산출물 생성 직후 상태를 갱신하는 습관. 갱신되지 않은 산출물은 "없는 것"으로 간주.
5. **ID 추적성**: REQ-F-001 → F-001 → API-001 → SCR-001 → TC-001. Group A 4개 산출물이 동일 F-ID 체계를 공유해야 정합성이 성립.
6. **AI 80% + PM 20%**: AI가 초안을 생성하고 PM이 전략적 판단(우선순위, 범위, 차별화)을 수행하는 역할 분담.

### 주의 사항

- 마켓리서치 웹 검색은 시간이 오래 걸린다. 통합자료실의 `참고자료/디지털콘텐츠_커머스_트렌드.md`로 대체 가능
- P-303 실행 시 정책자료(결제정책, 개인정보처리방침) 참조를 반드시 지시
- P-304 기능명세서가 정확해야 P-309 Group A 4건의 품질이 결정된다. 분기점이므로 검수에 더 시간 투자
- P-309 병렬 실행 시, 4개 서브에이전트가 각자 `.progress.md`를 동시에 수정하면 충돌 발생 가능. 반드시 "4개 산출물 완료 후 마지막에 한 번만 일괄 갱신" 지시
- Mermaid 다이어그램 문법에서 특수문자(괄호, 따옴표)로 인한 렌더링 오류 빈번. GitHub에서 확인 후 수정
- 화면설계서 ASCII 와이어프레임은 그대로 사용하지 말고, PM이 사용자 흐름을 상상하며 빠진 요소를 보완
