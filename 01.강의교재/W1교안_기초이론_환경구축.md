#### Backend 배치 전략 — 마일스톤별 (V0.42 정책)

본 과정은 **1인/소규모 운영을 기본 전제**로 하며, 백엔드 배치를 마일스톤 단계에 따라 진화시킨다:

| 단계 | API 위치 | 배포 | `src/backend/` 폴더 |
|------|---------|------|-------------------|
| **M1 ~ M4 (강의 5주차 범위)** | **`src/frontend/app/api/*`** (Next.js Route Handlers) | Vercel 단일 배포 | 빈 폴더 (`.gitkeep`) — 미사용 |
| **M5+ (트래픽 증가 시 분리 검토)** | `src/backend/` (Express.js) | Render / Railway 등 | 활성화 |

**왜 M1~M4는 통합인가**:
- 1인 운영 부하 최소화 (1개 프로젝트, 1개 배포)
- 비용 효율 (Vercel Hobby 무료 / Pro $20만)
- 콜드스타트 빠름 (Vercel Edge/Lambda)
- 마이그레이션 용이 (API Routes → Express로 자연스럽게 이전)

**W4 구현 자동화 시 핵심 지침**:
- **모든 API 코드는 `src/frontend/app/api/*`에 작성** (또는 Pages Router 사용 시 `pages/api/*`)
- `src/backend/`는 `.gitkeep`만 두고 비워둠 → M5 분리 시 동일 자리에 Express 코드 추가
- 인프라아키텍처(#10) 산출물에서 "M1~M4 통합 / M5+ 분리 검토" 정책 반드시 명시

> 자세한 내용은 `02.AP-Framework-V0.42/CLAUDE.template.md`의 **"Tech Stack > Backend 배치 전략"** 및 **"Deployment Architecture"** 섹션 참조.

### 2.3 Repo Clone (수강생 실습 전 완료)

Antigravity 통합 터미널 또는 일반 터미널(Terminal.app / iTerm2)에서 실행:

```bash
# 원하는 위치로 이동 (예: 홈 디렉토리)
cd ~

# Private repo clone
git clone https://github.com/rodipark/AP-Lecture-01.git

```

**Clone 시 인증 프롬프트가 나타나면**:

| 프롬프트 | 입력 |
|---------|------|
| `Username for 'https://github.com':` | 본인 GitHub **사용자명** (예: `studentXX`) |
| `Password for 'https://...':` | ⚠ 비밀번호가 아니라 **PAT (Personal Access Token)** 입력 |

> 매번 PAT를 입력하기 번거롭다면 macOS는 `git config --global credential.helper osxkeychain` 으로 1회만 입력 후 keychain에 자동 저장.

### 2.8 트러블슈팅

| 현상 | 원인 | 해결 |
|------|------|------|
| Clone 시 `Permission denied (repository not found)` | Collaborator 초대 미수락 또는 PAT 권한 부족 | ① 초대 메일에서 Accept 확인 ② PAT에 `repo` 권한 체크 후 재발급 |
| Clone 시 사용자명/비밀번호 무한 반복 | 비밀번호 입력 (PAT가 아님) | 비밀번호 대신 **PAT** 입력 |
| `./setup.sh: Permission denied` | 실행 권한 없음 | `chmod +x setup.sh` |
| `command not found: uv` (setup.sh 실행 직후) | PATH 미반영 | 새 터미널 열기 또는 `source ~/.zshrc` |
| `nlm login` Chrome 안 열림 | Chrome 미설치 또는 포트 충돌 | Chrome 설치 → 다른 Chrome 창 모두 닫고 재시도 |
| Antigravity 사이드 패널에서 스킬 안 보임 | Antigravity 캐시 | Antigravity 완전 종료 (Cmd+Q) 후 재실행 |

해결되지 않으면 Slack 교육 채널에 **스크린샷 + 에러 메시지 전문**과 함께 질문해주세요.

## 3. Twin Demo 구조 안내 (강의 진행 방식)

**핵심 메시지**: "AP-Rodi-Shop (정답지) + rodi-book (강사 라이브 빌드) + 수강생 본인 프로젝트 — 세 트랙이 함께 달린다"

### 3.1 세 블록의 역할 분리

| 블록 | 프로젝트 | 진행 형태 | 수강생 역할 | 본 주차 용도 |
|------|---------|----------|------------|------------|
| **Block A** (Part A 끝) | **AP-Rodi-Shop** (완성) | 강사 화면 공유 투어 | **관찰** | 5주 후 결과물 미리보기 (동기 부여) |
| **Block B** (Part B) | **rodi-book** (강사 라이브 빌드) | 강사 단계별 시연 | **관찰 + 메모** (따라치지 않음) | P-101 ~ P-104 전체 흐름 학습 |
| **Block C** (Part C) | **수강생 본인 프로젝트** | 수강생이 직접 수행 | **실행 (P-101 + P-102)** | W1 종착점: PRD + AP-Framework 셋팅 |

### 5.2 LLM = 확률적 텍스트 생성기

| 강점 | 한계 |
|------|------|
| 텍스트 생성(보고서·기획서 초안) | 할루시네이션 |
| 코드 작성 (프론트/백) | 최신 정보 부재 |
| 분석 / 요약 / 번역 | 복잡한 계산 오류 |
| 반복 업무 자동화 | 긴 컨텍스트의 맥락 손실 |

**AI가 가속하는 영역 vs PM이 판단하는 영역**:

| AI가 가속 (80%) | PM이 판단 (20%) |
|----------------|-----------------|
| 문서 초안 작성 | 이해관계자 협상 |
| 코드 자동 생성 | 비즈니스 전략 결정 |
| 테스트 시나리오/코드 | 품질 기준 · 릴리스 결정 |
| 데이터 분석 · 리서치 | 팀 관리 · 동기 부여 |
| 반복 보고서 | 위기 · 변경 관리 |

### 5.3 왜 Agent PM 인가 + 핵심 스킬 + 작동 원리

**시장의 변화**:
- 단위 업무(기획 · 디자인 · 퍼블리싱) 경계가 사라짐
- 2주 기획할 시간에 2주 만에 제품을 만든다
- 산출물은 빨라지고, **PM 판단의 가치는 더 커진다**

**Agent PM 핵심 스킬 4가지**:

| 스킬 | 설명 |
|------|------|
| Domain Expert | 비즈니스/도메인 이해 |
| Auto Workflow | 자동화 파이프라인 |
| Vibe Coding | 코드를 읽고 판단하는 PM |
| Smart Framework | AP-Framework V0.42 |

**Agent PM 작동 원리 3가지**:
1. **CLAUDE.md 기반 컨텍스트 설계** -- 프로젝트 규칙을 영구 시스템 프롬프트로
2. **산출물 체이닝** -- 이전 결과가 다음 입력
3. **PM 역할 전환** -- '지시하는 사람' → '설계하고 검증하는 사람'

> **강사 노트**: "AI가 PM을 대체한다"가 아니라 "AI가 PM의 반복 업무를 자동화하여, PM이 판단 업무에 집중하게 한다"로 프레이밍.

### 5.4 Anthropic Claude 생태계 + Antigravity 플러그인

| 제품 | 형태 | 주 용도 | 비용 |
|------|------|---------|------|
| Claude Pro (웹) | 웹 채팅 | 브레인스토밍 | $20/월 |
| Claude API | API | 앱 통합 | 사용량 |
| Claude Code (CLI) | 터미널 | 스크립트/자동화 | Pro/Max 포함 |
| **★ Claude Code 플러그인 (Antigravity)** | **IDE 내장** | **본 과정 표준** | **Pro/Max 포함** |

**Claude 웹 vs Antigravity 플러그인**:

| 단계 | Claude 웹 | Antigravity 플러그인 |
|------|-----------|---------------------|
| 동작 | 채팅 텍스트만 (파일 접근 X) | 에디터에 즉시 갱신 (Read → Write) |
| 검토 | 사용자가 복사/붙여넣기 | **diff 뷰**로 변경 부분 시각화 |
| 결정 | 별도 행동 없음 | **Accept / Reject** 클릭 |
| Git | 별도 행동 없음 | 좌측 Source Control 자동 반영 |

> **강사 노트**: 플러그인의 "마법"은 **diff 뷰 + Accept/Reject + Git 통합**. **Part B (Block B) 에서 실제로 보여준다**.
